# V6: экономное подтверждение близких лидеров

План зарегистрирован 9 ноября 2026 года до новых API-вызовов. Предыдущий [V5](../v5/README.md) сохранён без изменений. Первый запуск 9 ноября в 23:10 МСК остановился: HTTP 402 `Insufficient credits`. Завершённых ответов нет. Сохранились 25 попыток (один явный отказ и 24 запроса без зафиксированного ответа); их стоимость неизвестна. Для новых результатов необходимо пополнение аккаунта. Лимит ключа и баланс аккаунта являются разными величинами; положительный остаток лимита не подтвердил наличие средств.

## Что проверяется

Все варианты продолжают идею V5: шесть фиксированных схем, shared-оценка на 24 задачах и дополнительное подтверждение близких лидеров. Модель, промпты, temperature 0.2, max_tokens 8192 и оценщик рационального ответа сохранены. Используется `openai/gpt-4.1-nano` через OpenRouter; провайдер не закреплён.

| Вариант | Изменение относительно V5 |
|---|---|
| V5 | Контроль: независимо проверить всех кандидатов в пределах одного правильного ответа от лидера на восьми задачах |
| `race8` | Проверять reserve-задачи по одной и отсеивать кандидата только тогда, когда даже все оставшиеся правильные ответы уже не позволят ему выиграть с учётом фиксированного разрешения ничьих |
| `top2` | На восьми задачах независимо проверять только двух лучших близких лидеров |
| `weighted8` | Увеличить вес каждого правильного ответа независимого подтверждения до двух |
| `race16` | Подтверждать до 16 задач с таким же безопасным отсевом. Здесь больше данных, чем у V5 и полного варианта; эффект отсева отдельно не изолируется |
| `shared8` | Диагностика: восемь подтверждающих задач с общими корневыми ответами. В финальный отбор этой серии не допускается |

У `race8` победитель должен совпадать с полным V5 на любой фиксированной таблице ответов. Экономится только оценивание кандидатов, которые уже не могут выиграть. Это свойство проверено на 3000 случайных таблицах в программных тестах; эти тесты не являются экспериментами качества LLM.

## Разделение данных

Из исходных сохранённых снимков MATH выбраны 160 новых задач Level 5 с рациональным эталоном, без рисунков: Algebra и Intermediate algebra поровну. Исключены все 296 вопросов предыдущих запусков. Все части V6 взаимно непересекающиеся.

| Этап | Первичный выбор | Reserve | Проверка |
|---|---:|---:|---:|
| Разработка, два повтора | 24 | 16 | 16 задач исходной train-части |
| Финальная проверка одного варианта, три повтора | 24 | 16 | 64 задачи исходной test-части |

V5 и полный независимый вариант используют первые восемь reserve-задач; 16 нужны только гипотезе `race16`. Между повторами задачи повторяются, ответы свежие. Это 64 уникальные финальные задачи, а не 192 независимые задачи. Эталоны не включаются в запросы модели.

На этапе разработки собираются таблицы ответов всех необходимых схем, затем правила отбора применяются к ним без дополнительных запросов. Решения каждого правила записываются до запросов на 16 задачах разработки. Изменять правила после этих результатов нельзя.

В следующий этап проходит вариант, который на двух повторах разработки:

1. Не уступил V5 по суммарному числу правильных ответов.
2. Сохранил не менее 20% известных расходов выбора относительно полного независимого оценивания.
3. Дал хотя бы один дополнительный правильный результат либо уменьшил известную стоимость выбора V5 минимум на 5% при той же точности.
4. Не имеет неизвестной стоимости попыток поиска на этапе разработки.

Среди прошедших выбирается один: больше правильных ответов, затем ниже стоимость, затем заранее заданный порядок вариантов. Если никто не прошёл, финальный тест не запускается. На финальных задачах сравниваются полный независимый вариант, неизменённый V5 и выбранная надстройка. Повторного выбора гипотез по финальному тесту нет.

## Расходы и ограничения

Стоимость стратегии считается по уникальным вызовам, которые она использовала бы при последовательном исполнении. Совпадающие вызовы контрольного и нового метода переиспользуются как общие случайные ответы. Фактический исследовательский счёт включает объединение всех собранных таблиц, контрольных методов и тестов. Его нельзя выдавать за стоимость одной стратегии или складывать стоимость одинаковых вызовов несколько раз.

Указанные в журнале API-расходы первичны; неизвестная стоимость сохраняется отдельно. Повторы только транспортных ошибок: максимум два, с общими паузами 30/60 секунд. HTTP-отказы не повторяются. Лимит всей серии разработки и финальной проверки составляет 10800 секунд. При превышении серия останавливается, незавершённые запросы остаются с неизвестной стоимостью. Автоматического изменения критериев или задач нет.

Ожидаемый верхний объём до повторов ошибок: 7768 вызовов. Ориентир расходов $3–7, без денежной отсечки. Время зависит от сервиса: лимит три часа ограничивает выполнение, но не гарантирует завершения. Программные проверки до запуска: Ruff и Ty прошли; 346 тестов пакетов и новой процедуры прошли.

Наблюдаемое улучшение на этапе разработки само по себе не считается подтверждением. Даже положительная отдельная проверка останется ограниченной одной моделью, двумя доменами и фиксированным банком. AFlow/ADAS не являются контрольными методами этой серии.

## Воспроизведение

`plan.json` содержит все задачи, промпты, критерии и хеши исходников. `source.zip` содержит полный снимок исходного кода V6 с `uv.lock`. Подготовьте окружение как в [полном V5](../v5/full-reproduction/README.md), но используйте исходники V6:

```sh
python -m zipfile -e source.zip .
cd runtime-source
uv sync --frozen --all-packages --group paperbench
uv run --frozen python -m benchmarks.workflow_search.progressive --plan /absolute/new-runs/plan.json --name v6-fresh --env-file /absolute/private/.env
```

Скопируйте `plan.json` в отдельный `new-runs`. Результаты будут созданы рядом с планом; имя запуска должно быть новым. Ключ API не входит в архив. Перед новым платным запуском нужно отдельно проверить `GET /api/v1/credits` (баланс аккаунта) и `GET /api/v1/key` (лимит ключа). Для предотвращения idle-сна и сохранения stdout запускайте через `benchmarks.workflow_search.record --keep-awake`, как в инструкции V5.

## Продолжение после неудачного старта

`startup-records.zip` содержит первый остановленный запуск и его команды, вывод и попытки. В `operational-amendment.json` зафиксирована проверка реального баланса перед продолжением. Эта поправка сделана до первого завершённого ответа V6; задачи, определения гипотез, scoring и критерии выбора не менялись.

После пополнения, из каталога исходников:

```sh
uv run --frozen python -m benchmarks.workflow_search.record --output /absolute/workflow-runs/commands/main-v6-progressive-recovery1 --keep-awake -- uv run --frozen python -m benchmarks.workflow_search.resume_progressive --source /absolute/workflow-runs/main-v6-progressive-20261109 --plan /absolute/workflow-runs/main-v6-progressive-plan.json --name main-v6-progressive-recovery1 --env-file /absolute/private/.env
```

Обработчик сначала проверяет деньги, затем побайтно сохраняет исторические 25 попыток в `startup_attempts/calls` и начинает измеряемый прогон с тем же планом. Стоимость этой неудачи старта остаётся неизвестной и включается отдельной статьёй в общий исследовательский счёт. Условия отбора гипотез применяются к новым измеряемым поисковым вызовам; неизвестная стоимость в них по-прежнему блокирует выбор победителя. Первоначальный каталог не изменяется. Такой обработчик применим только к первому старту без завершённых ответов; восстановление после частично успешной серии потребует отдельной проверки.

## Дополнительная офлайн-проверка V5

В [v5-replay.json](v5-replay.json) сохранён расчёт `race8` на исторических ответах V5. Все три победителя совпали; из 264 подтверждающих вызовов потребовались бы 240. Проекция известных расходов выбора: $0.56536972 вместо $0.58087392, снижение на 2,67% относительно V5 (33,57% относительно полного режима).

Это не новый прогон LLM и не измерение реального времени: использована уже известная таблица V5. Старые 13 попыток с неизвестной стоимостью остаются неизвестными. Код пересчёта находится в `replay_v5.py`; он требует исходного рабочего пространства и Python-окружения FEDOT.Swarm. Само правило `race8` реализовано в `source.zip`.
